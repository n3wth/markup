Search Experience Direction

Which approach feels right for Markup's search?

A

Unified Spotlight

A single Cmd+K overlay that replaces the current command palette. Searches across everything: document titles, document content, agent chat messages, and commands — all in one ranked list with category labels. Think Raycast or Arc's command bar.

Pros

  • One shortcut to remember
  • Fastest path to anything
  • Natural upgrade from existing Cmd+K

Cons

  • Mixed result types can feel noisy
  • Needs good ranking to avoid clutter
B

Layered Search (Sidebar + Overlay)

Keep the sidebar search for quick document filtering, but add a rich search overlay (via the search icon or Cmd+Shift+F) that opens a full panel for deep content search with snippet previews, conversation search, and filters. Like ChatGPT's search icon or Notion's search page.

Pros

  • Quick filter stays fast
  • Deep search gets proper space
  • Can show rich previews and context

Cons

  • Two search experiences to learn
  • More UI surface area
C

AI-Native Search

A conversational search interface where you can ask natural language questions like "find the doc where Aiden disagreed about the API design" or "which PRD mentions the billing feature?". Uses Gemini to semantically match across docs and conversations. Results appear as cards with context.

Pros

  • Uniquely powerful for AI-native editor
  • Can surface insights, not just matches
  • Differentiator vs every other editor

Cons

  • Latency (LLM call per search)
  • Expensive at scale
  • Hard to get right without embeddings infra
